## 售后处理意图实现文档

### 槽位信息
1. order_id：订单id
2. postsale_type：售后类型。可选值：_POSTSALE_TYPES = {
    "refund_only": "仅退款",
    "return_refund": "退货退款",
}
3. postsale_reason：售后原因。可选值：_POSTSALE_REASONS = [
    "7天无理由",
    "商品瑕疵/破损",
    "发错货",
    "商品与描述不符",
    "质量问题",
    "不喜欢/不想要了",
]

### handle执行流程
1. 先判断槽位中是否存在order_id，如果没有，那么就查找数据库，获取该用户最近最多5条订单数据，后期在页面中通过按钮的形式展示出来，让用户点击选择具体的order_id
2. 再判断槽位中是否存在postsale_type，如果没有，那么就返回_POSTSALE_TYPES，并且在页面中以按钮的形式展示出来，用户点击某个选项后就将该槽位值发送给服务器。
3. 最后判断槽位中是否存在postsale_reason，如果没有，那么就返回_POSTSALE_REASONS，并且在页面中以按钮的形式展示出来，用户点击某个选项后就将该槽位值发送给服务器。

直到三个槽的值都有了，才真正执行售后处理，这里简化售后流程，直接通过售后，将订单的状态改为：售后中
